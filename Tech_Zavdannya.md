# Технічне завдання (спрощене)

**Проєкт:** Raw Material Accounting System in Manufacturing  
**Документ:** спрощене ТЗ (класичний підхід до фіксації вимог на початку проєкту)

---

## 1. Мета і завдання продукту

### 1.1. Мета

Створити веб-систему обліку сировини на виробництві, яка забезпечує прозорий контроль руху матеріалів від закупівлі до списання у виробництво, зменшує втрати та спрощує звітність для складу й керівництва.

### 1.2. Завдання продукту

1. Зафіксувати надходження, видачу та списання сировини в єдиній системі.
2. Показувати актуальні залишки на складах у розрізі матеріалів.
3. Прив’язувати витрати сировини до виробничих партій / замовлень.
4. Формувати звіти про рух, витрати та дефіцит за період.
5. Обмежити доступ до функцій за ролями користувачів.

---

## 2. Загальні функціональні вимоги

| ID | Вимога |
|----|--------|
| FR-01 | Реєстрація надходження сировини (матеріал, кількість, партія, постачальник, дата) |
| FR-02 | Видача / списання сировини у виробництво з прив’язкою до виробничої партії |
| FR-03 | Перегляд актуальних залишків по складах і матеріалах |
| FR-04 | Звіти про рух, витрати та дефіцит за вибраний період |
| FR-05 | Розмежування доступу: адміністратор, склад, закупівлі, технолог, бухгалтер, аналітик |

---

## 3. Загальні нефункціональні вимоги

| ID | Вимога |
|----|--------|
| NFR-01 | Автентифікація користувачів і авторизація дій за роллю |
| NFR-02 | Список залишків і типовий звіт відкриваються ≤ 3 с при типовому обсязі даних |
| NFR-03 | Коректна робота веб-інтерфейсу в Chrome, Firefox, Edge |
| NFR-04 | Операції обліку виконуються транзакційно (без часткового збереження при збої) |
| NFR-05 | Основні складські дії доступні без тривалого навчання |

---

## 4. Обмеження

1. **Обсяг першої версії** — лише облік сировини, залишки, базові звіти та ролі; без повного ERP, CRM і складного виробничого планування.
2. **Платформа** — веб-застосунок; мобільний нативний клієнт не входить у перший реліз.
3. **Вимоги фіксуються на початку** (класична модель ЖЦ): зміни після затвердження ТЗ потребують окремого узгодження.
4. **Дані** — облік ведеться в межах одного підприємства / кількох складів одного підприємства.
5. **Інтеграції** — зовнішні бухгалтерські та складські системи в першій версії не обов’язкові.
6. **Ресурси** — навчальний / курсовий проєкт: обмежений час і команда, пріоритет — робочий MVP за затвердженими вимогами.

---

## 5. Очікувані результати

1. Затверджене ТЗ та узгоджені функціональні / нефункціональні вимоги.
2. Робочий веб-прототип (MVP), що реалізує FR-01…FR-05.
3. Рольовий доступ відповідно до NFR-01 та FR-05.
4. Можливість перевірити залишки, рух сировини та базові звіти на тестових даних.
5. Документація достатня для приймання результату за класичним підходом (перевірка відповідності ТЗ).

---

## 6. Критерії приймання (коротко)

Продукт вважається прийнятим, якщо:

- усі пункти FR-01…FR-05 доступні для відповідних ролей;
- нефункціональні обмеження NFR-01…NFR-05 виконуються на тестовому середовищі;
- результати відповідають меті та завданням розділу 1 у межах обмежень розділу 4.
